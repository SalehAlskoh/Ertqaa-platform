## المصادقة والصلاحيات

تسجيل الجلسة باستخدام Laravel Session Authentication؛ كلمات المرور مجزأة عبر cast `hashed`. التسجيل العام ينشئ دور student فقط داخل Transaction مع الملف. حقول الدور والتفعيل ممنوعة في طلب التسجيل. عند الدخول تُجدد الجلسة، وتُحدد المحاولات حسب البريد/IP مع حد إضافي للمسار. الخروج يبطل الجلسة ويجدد CSRF، وتغيير كلمة المرور يتطلب الحالية وتأكيدًا بطول 12 حرفًا على الأقل.

- Admin: التصنيفات والكورسات والمجموعات والمحاضرون والموظفون.
- Staff: التصنيفات والكورسات والمجموعات فقط؛ لا إدارة حسابات ولا تعديل أدوار.
- Instructor: ملفه المهني ومجموعاته فقط؛ تغيير ID لا يمنحه وصولًا إلى مجموعة أخرى.
- Student: ملفه الشخصي والعرض العام للمنشور؛ لا تقديم على مجموعة في هذه المرحلة.
- Guest: العرض العام للمنشور والتسجيل الطلابي والدخول.

لا تعتمد الحماية على الأزرار المخفية. لا مسار عام لإنشاء مدير، ولا كلمة مرور ثابتة في Seeder. أمر `ertqaa:create-admin` يرفض الحساب الموجود ويقبل كلمة مخفية تفاعليًا أو stdin صريحًا دون وسيطة لكلمة المرور.

## نتائج فحوص التشغيل الفعلية

- قاعدة فحص مستقلة: إنشاء جدولين، كتابة وقراءة، Rollback وCommit، رفض FK غير صالح وCHECK مخالف. بقيت السجلات بعد إيقاف الخادم الجديد طبيعيًا وتشغيله؛ حُذف جدولا الفحص اللذان أُنشئا فقط، وبقي مخطط الفحص فارغًا.
- تطبيق أربعة Migrations بما فيها الافتراضية؛ `migrate:status` يعرض Ran. Seeder الأدوار شُغّل مرتين وبقيت أربعة أدوار فقط. بعد إعادة تشغيل نهائية بالخادم المستقل ظلت الجداول الـ23 والأدوار الأربعة موجودة، مع 18 مفتاحًا أجنبيًا و7 قيود CHECK، ولا أخطاء ERROR في سجل الخادم الجديد.
- استُنشئت علاقات Models المصرح بها دون أخطاء، وفُحصت الجداول والقيود عبر information_schema.
- المتصفح: تسجيل طالب، دخول وخروج، إنشاء تصنيف وكورس ومحاضر وموظف ومجموعة منشورة، ربط دور المحاضر بحساب طالب موجود، وصفحات التفاصيل والتعديل.
- تحديث التصنيف والكورس والمحاضر والموظف والمجموعة عبر طلبات فعلية؛ تأكدت القيم المخزنة (ساعات الكورس 15 والسعة 21 والخبرة 6) قبل إزالة بيانات المراجعة.
- تحديث كلمة المرور من نموذج الملف الشخصي وفحص التجزئة نجح. ضبط is_active لحساب المراجعة مباشرة في القاعدة ألغى وصول جلسته عند طلب صفحة محمية، ومحاولة دخوله رُفضت 422.
- إضافة role=admin إلى التسجيل رُفضت 422؛ حد محاولات الدخول فعّل رسالة الانتظار عند المحاولة السادسة.
- طالب يطلب الإدارة: 403. موظف يطلب الكورسات والمجموعات: 200، والمحاضرين والموظفين: 403.
- محاضر يطلب مجموعته وملفه: 200، ومجموعة محاضر آخر أو الإدارة: 403.
- السعة صفرًا والتواريخ المعكوسة: 422. نشر مجموعة لكورس غير منشور: 422. كورس غير منشور في رابط عام: 404.
- حذف تصنيف أو كورس مرتبط: 403. الصفحات العامة لا تعرض بريد المحاضر.
- فحص الإشغال داخل Transaction تم التراجع عنها: عرض صالح = حجز واحد؛ إضافة تسجيل نشط لنفس العرض حُسبت مرة واحدة؛ رفض تخفيض السعة عن حجزين قائمين.
- `route:list` يعرض 50 مسار تطبيق. فحص PHP Syntax لـ47 ملفًا وBlade compilation وبناء Vite نجحت. أعادت courses وgroups وlogin وregister وup حالة 200 بعد التنظيف وإعادة التشغيل. تقييم بصري للصفحات العامة والمصادقة مرّ على 1440 و768 و375px.
- لم تُنشأ أو تُشغل PHPUnit أو Feature Tests آلية؛ الفحوص كانت أوامر تشغيل وفحص قاعدة ومتصفح.
- أُزيلت السجلات والحسابات المؤقتة الأربعة التي أُنشئت للمراجعة فقط؛ لم يُترك مدير افتراضي أو بيانات عرض وهمية. بقيت الأدوار الأربعة، وصفحات القوائم تعرض حالاتها الفارغة.

## المشكلات والإصلاحات

1. تلف/عدم تطابق ملفات XAMPP: حُفظت دون إصلاح مدمر، وفُحصت نسخة معزولة، واعتمدت قاعدة جديدة بقرار المستخدم. **البيانات القديمة ليست مستعادة.**
2. انقطاع تنزيل الحزمة: استُؤنف التنزيل ثم طابقت البصمة المنشورة.
3. Model Role حاول استخدام أعمدة توقيت غير موجودة: عُطّلت timestamps بما يطابق العقد.
4. توجيهات Blade متلاصقة أظهرت include كنص: فُصلت التوجيهات وأُعيد التحقق من الحقول في المتصفح.
5. إعادة توجيه طلب PATCH الخام احتفظت بالطريقة مع 302: استُخدمت استجابة 303 بعد العمليات الناجحة، ثم نجحت التحديثات الخمسة وتأكدت القيم المخزنة.
6. إدخال كلمات مخفية عبر pipe لا يحاكي الطرفية: أُضيف وضع stdin صريح للأمر الإداري، واستُخدم بنجاح دون طباعة الكلمة.

## الاختلافات والحدود

لم يُعدّل المرجع العلائقي. الاستخدام المعتمد هو MariaDB بدل MySQL الفعلي مع `DB_CONNECTION=mysql` بقرار المستخدم. الجداول كلها أُنشئت كما أجازت خطة التنفيذ الأحدث، دون تنفيذ الافتراضات المفتوحة لدورة التسجيل والمحاضرات والإشعارات.

العرض العام للمجموعات يقتصر على الحالة published وكورس منشور؛ انتهاء فترة التسجيل وحده لا يخفي المجموعة. بقية الحالات محفوظة في الإدارة دون افتراض مصفوفة انتقالات جديدة. حماية السعة تحسب القائم من التسجيلات والحجوزات فقط، ولا تنشئ دورة تسجيل.

البريد الإنتاجي والتحقق بالبريد مؤجلان، ولم يُختبر إرسال بريد أو نشر إنتاجي. تقييم التصميم شمل الصفحات العامة والمصادقة؛ صفحات الإدارة فُحصت وظيفيًا عبر المتصفح، وليست شهادة اختبار شاملة لكل حجم شاشة أو كل حالات التزامن.

استعادة قواعد XAMPP القديمة عمل مستقل متبقٍ؛ ليست شرطًا للبيئة الجديدة بعد قرار المستخدم. لا توجد موافقة أخرى مطلوبة لاستعمال المنصة المحلية. لا Commit أو Push، ولا تغيير Git Remote. تعليمات تشغيل الخادم وإنشاء أول مدير وخطوات المراجعة في [LOCAL_DEVELOPMENT.md](LOCAL_DEVELOPMENT.md).
