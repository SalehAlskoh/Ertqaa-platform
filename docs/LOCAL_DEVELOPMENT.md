# تشغيل ارتقاء محليًا

## قاعدة البيانات المستقلة

هذه البيئة تستخدم MariaDB **11.4.13** محمولة خارج XAMPP:

- المجلد: `C:\Users\hp\AppData\Local\Ertqaa-MariaDB-11.4.13`.
- العنوان: `127.0.0.1:3308`، قاعدة المشروع: `ertqaa_platform`.
- `DB_CONNECTION=mysql`، الترميز `utf8mb4`، Collation هو `utf8mb4_unicode_ci`.
- حساب التطبيق `ertqaa_app` محصور بهذه القاعدة، وكلمة مروره داخل `.env` المتجاهل في Git.
- بيانات الإدارة المولدة محفوظة في `.env` داخل مجلد التشغيل المستقل؛ لا تُنسخ إلى المستودع ولا تُعرض في السجلات.
- الخادم ليس خدمة Windows، لذلك يحتاج تشغيلًا بعد إعادة تشغيل الجهاز. لا يلزم تشغيل MySQL من XAMPP للمنصة.

## التشغيل اليومي بأمر واحد

من جذر المشروع في PowerShell، بعد تشغيل الجهاز:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-ertqaa.ps1
```

السكربت يحدد مسار المشروع من مكانه، لذلك يظل صالحًا بعد نقل المجلد، ويتحقق بالتتابع من:

1. MariaDB على `3308`: يعيد استخدام العملية الحالية إذا كانت الخادم المستقل المعتمد، أو يستدعي `scripts/start-local-db.ps1` إذا كانت متوقفة، ثم ينتظر جاهزية المنفذ.
2. اتصال Laravel الفعلي: يحمّل إعداداته الحالية، بما فيها Config Cache إن وجد، وينفذ استعلام قراءة للتحقق من قاعدة `ertqaa_platform` عبر `mysql` على المنفذ المحلي `3308`. لا يطبع كلمات المرور أو رسائل الاستثناء الخام.
3. Laravel على `8000`: يعيد استخدام خادم هذا المشروع أو يشغّل `php artisan serve` في الخلفية، ثم يتحقق من استجابة صفحة المنصة. إذا كان المنفذ يخص عملية أخرى، يعرض خطأ دون إيقافها أو اختيار منفذ بديل.

يمكن تكرار الأمر؛ لا ينشئ عمليات أخرى للخدمات العاملة، وتُسلسل محاولات التشغيل المتزامنة. يعرض رسائل نجاح أو فشل بالعربية، ويعيد Exit Code بقيمة `0` عند النجاح و`1` عند الفشل. يمكن إغلاق نافذة أمر التشغيل بعد النجاح؛ تشغيل الخدمات لا يعتمد على بقاء تلك النافذة مفتوحة، لكن يلزم إعادة الأمر بعد إغلاق الكمبيوتر أو إعادة تشغيله.

افتح `http://127.0.0.1:8000`. الأصول مبنية بالفعل؛ لا يشغّل السكربت NPM أو Vite أو Scheduler تلقائيًا. بعد تعديل الواجهات شغّل `npm.cmd run build`، أو `npm.cmd run dev` في نافذة أخرى أثناء التطوير.

لا يعدّل السكربت `.env` أو إعدادات قاعدة البيانات، ولا يحذف بيانات، ولا يمسح Config Cache، ولا ينفذ Migrations أو Seeders. تشغيل `php artisan migrate` يكون يدويًا عند إضافة Migrations معتمدة، وتهيئة الأدوار عند إعداد بيئة جديدة فقط؛ لا تكرر أوامر التهيئة عند كل تشغيل. لا تشغّل `composer setup` لإعداد مشروع قائم؛ فهو يولّد مفتاح تطبيق جديدًا.

للتشخيص:

- سجل MariaDB: `C:\Users\hp\AppData\Local\Ertqaa-MariaDB-11.4.13\server.log`.
- سجل التطبيق: `storage/logs/laravel.log`.
- عند إنشاء خادم Laravel جديد: ملفا `storage/logs/ertqaa-server-*.out.log` و`storage/logs/ertqaa-server-*.err.log`؛ يحفظ كل تشغيل ملفات جديدة بدل استبدال السجلات السابقة، وهي مستثناة من Git.
- إذا عملت المنافذ وفشل فحص قاعدة البيانات، راجع إعدادات `.env` دون نشر أسرارها. إذا كنت قد عدّلت الإعدادات وكان Config Cache قديمًا، نفذ `php artisan config:clear` يدويًا ثم أعد أمر التشغيل؛ السكربت لا يغيّر الإعدادات لمعالجة الخطأ.

يبقى `scripts/start-local-db.ps1` متاحًا لتشغيل قاعدة البيانات وحدها عند الحاجة.

إذا غاب مجلد التشغيل في جهاز آخر، جهّز نسخة MariaDB مستقلة مدعومة ببيانات جديدة وبيانات اتصال خاصة بذلك الجهاز؛ ملف `.env.example` قالب وليس بيانات دخول جاهزة. الحزمة المستخدمة هنا من [أرشيف MariaDB الرسمي](https://archive.mariadb.org/mariadb-11.4.13/winx64-packages/)، وقد طابقت بصمة SHA-256 المنشورة قبل فكها.

## أول حساب مدير

تسجيل الدخول موحد للجميع عبر `/login`. يختار `/dashboard` لوحة الدور بأولوية Admin ثم Staff ثم Instructor ثم Student، دون حذف الأدوار الأخرى. رابط العودة المحفوظ يُستخدم فقط إذا كان محليًا وآمنًا ويجتاز صلاحيات المسار وملكية السجل؛ وإلا يُستخدم التوجيه الافتراضي. التسجيل العام ينشئ طالبًا فقط، ولا يمنح نموذج Login أدوارًا.

في بيئة `APP_ENV=local`، يدعم `AdminSeeder` تجهيز مدير من القيم التالية داخل `.env` المحلي فقط:

```dotenv
SEED_ADMIN_NAME=
SEED_ADMIN_EMAIL=
SEED_ADMIN_PASSWORD=
```

ضع الاسم والبريد الحقيقيين وكلمة مرور خاصة تختارها محليًا؛ القيم الفارغة أعلاه ليست حسابًا افتراضيًا. كلمة المرور المطلوبة 12 حرفًا على الأقل، تتضمن أحرفًا كبيرة وصغيرة وأرقامًا ورموزًا. استخدم علامات اقتباس مفردة للقيم التي تحتوي مسافات أو `#` أو `$` لتبقى حرفية في Dotenv، ولا ترسل كلمة المرور عبر المحادثة أو تضفها إلى Git أو وسيطات الأوامر.

ثم نفذ من جذر المشروع:

```powershell
php artisan config:clear
php artisan db:seed
```

ينفذ `DatabaseSeeder` زرع الأدوار أولًا ثم `AdminSeeder`، دون إنشاء مستخدمين تجريبيين. عند غياب أي قيمة يُتخطى إنشاء المدير برسالة واضحة وتبقى الأدوار مزروعة. عند توفر القيم الصحيحة ينشئ مديرًا نشطًا ويربطه بدور `admin` داخل Transaction. لا ينشئ مديرًا بهذه الطريقة في Production أو أي بيئة غير `local`.

إعادة التشغيل آمنة: البريد الذي يخص مديرًا قائمًا لا يكرر الحساب ولا يغير اسمه أو كلمة مروره أو أدواره أو حالة نشاطه. البريد الذي يخص حسابًا بلا دور `admin` يسبب خطأ تعارض دون ترقية الحساب. حساب المدير المعطل لا يُفعّل تلقائيًا. بيانات الإنشاء غير الصالحة تُرفض دون إنشاء حساب جزئي.

بعد إنشاء الحساب، احذف `SEED_ADMIN_PASSWORD` من `.env` أو اتركه فارغًا، ثم نفذ `php artisan config:clear` لإزالة القيمة المؤقتة من Config Cache أيضًا. إذا كنت تستخدم `config:cache` فأعد بناءه بعد إزالة القيمة. لا يحذف ذلك المستخدم ولا كلمة مروره المجزأة في قاعدة البيانات. يقرأ Seeder من `config/admin_seed.php` لدعم Config Cache، ولا يوجد داخله سر ثابت.

يمكنك الاحتفاظ بمدير موجود وترك المتغيرات الثلاثة فارغة. هذا هو الخيار المتبع حاليًا في المشروع؛ اختُبر إنشاء المدير والدخول به في قاعدة معزولة، دون تغيير المدير الحالي.

يبقى الأمر الإداري الموجود وسيلة بديلة، ولم يتغير سلوكه:

```powershell
php artisan ertqaa:create-admin --name="اسم المدير" --email="admin@example.com"
```

يطلب الأمر كلمة مرور مخفية وتأكيدها، بطول 12 حرفًا على الأقل. لا تمرر كلمة المرور كوسيطة أمر. عند وجود البريد مسبقًا يرفض الأمر إنشاء الحساب أو تغيير أدواره. للأتمتة المحلية الموثوقة، يدعم `--password-stdin --no-interaction` مع `--name` و`--email`: يُقرأ سطران من stdin (الكلمة ثم تأكيدها)، دون طباعتهما أو حفظهما في الكود. لا يوجد حساب مدير افتراضي أو كلمة مرور ثابتة.

التسجيل العام ينشئ طالبًا فقط. أنشئ الموظفين والمحاضرين من قوائم المدير. لإضافة دور إلى حساب موجود، ابحث ببريده الدقيق وراجع هويته ثم اختر نمط الحساب الموجود وأكد العملية؛ لا تتغير كلمة مروره أو أدواره السابقة.

## مراجعة يدوية

1. سجّل طالبًا، راجع ملفه، عدّل بياناته وكلمة مروره، ثم جرّب الدخول والخروج.
2. بحساب المدير أضف تصنيفًا وكورسًا، وانشره. جرّب البحث والتصفية والتعديل.
3. أضف محاضرًا جديدًا أو اربط حسابًا موجودًا بعد التأكيد. أنشئ موظفًا من قائمة الموظفين.
4. أنشئ مجموعة واختر كورسًا ومحاضرًا نشطًا. جرّب السعة صفرًا والتواريخ المعكوسة: يجب رفضهما.
5. جرّب نشر مجموعة لكورس غير منشور: يجب رفض العملية. إلغاء نشر الكورس يخفيه ومجموعاته عن العامة.
6. ادخل كمحاضر: تظهر مجموعاته فقط؛ تغيير رقم الرابط إلى مجموعة محاضر آخر يُرفض بـ403.
7. ادخل كموظف: إدارة التصنيفات والكورسات والمجموعات متاحة، وإدارة المحاضرين والموظفين ممنوعة.
8. عطّل حسابًا مؤقتًا: تُرفض محاولات دخوله، وتُبطل جلسته عند طلب صفحة محمية.
9. جرّب حذف تصنيف مرتبط بكورس، أو كورس مرتبط بمجموعة: تُرفض العملية. استخدم إلغاء النشر للحفاظ على التاريخ.
10. جرّب الواجهات على الهاتف. فترة التسجيل تُدخل وتُعرض بتوقيت `Africa/Tripoli` وتُخزن UTC.

العرض العام للمجموعات محصور بالحالة `published` مع كورس منشور، حتى لو انتهت فترة التقديم. بعد Sprint 3 يظهر «تقديم طلب الانضمام» للطالب المؤهل خلال نافذة التسجيل وعند توفر المقاعد، ويظهر طلبه السابق بدل إنشاء طلب مكرر. الطلب المبدئي لا يحجز مقعدًا.

## تشغيل Sprint 3 ومراجعته

Migration الإضافية `2026_11_13_000001_add_confirmation_details_to_enrollments` مطبقة محليًا، وتضيف هوية المؤكد والمبلغ ووقت التحصيل. على جهاز آخر يكفي `php artisan migrate` على قاعدة معدة مسبقًا؛ لا تستخدم أوامر إعادة إنشاء الجداول. الوثيقة الأصلية مع [ملحق Sprint 3](SPRINT_3_SCHEMA_ADDENDUM.md) مرجع التنفيذ الحالي، ويتقدم الملحق على افتراض تأكيد الطالب القديم.

1. كطالب: افتح مجموعة منشورة بوقت تسجيل حالي ومقعد متاح، قدم طلبًا، ثم تابع «طلباتي». لا يظهر تأكيد نهائي للطالب.
2. كمدير/موظف: راجع «طلبات التسجيل»، وافق مبدئيًا أو ارفض بسبب. الموافقة تحجز 48 ساعة من أول اعتماد ولا تمددها إعادة الإرسال.
3. بعد حضور الطالب: افتح التأكيد الحضوري وسجل كامل الرسوم. الرسوم NULL تمنع التأكيد، والصفر الصريح مجاني. الموظف الحالي والوقت يسجلهما الخادم؛ لا تقسط ولا تسترد تلقائيًا. يثبت التسجيل المؤكد رسوم المجموعة وعملتها لحفظ التاريخ.
4. ولّد جدول المجموعة الفارغة من تاريخ يطابق الأيام المختارة وأوقات طرابلس. يمكن إضافة محاضرة مفردة أو تعديل المجدولة بسبب، أو إلغاؤها بسبب، أو إكمالها. المحاضر يشاهد مجموعاته وطلابها النشطين، ولا يعدل المحاضرات.
5. كطالب مسجل: راجع «تسجيلاتي» و«محاضراتي» و«إشعاراتي». الانسحاب يحفظ التحصيل ويحرر المقعد ويزيل الوصول لمحاضرات المجموعة؛ لا يعني استرداد الرسوم أو إعادة التفعيل.

أمر انتهاء العروض آمن وقابل للتكرار:

```powershell
php artisan ertqaa:expire-offers
php artisan schedule:list
```

الأمر مسجل كل دقيقة داخل Laravel Scheduler. أثناء التطوير يمكن تشغيل `php artisan schedule:work` في جلسة مستقلة، وعند النشر تُضبط استدعاءات `php artisan schedule:run` كل دقيقة في مجدول بيئة التشغيل. لم تُنشأ مهمة Windows أو خدمة نظام تلقائيًا. تحرير المقعد ورفض التأكيد بعد انتهاء المهلة يعتمدان على الوقت الفعلي ولا ينتظران المجدول؛ المجدول يحفظ الحالة ويرسل إشعار الانتهاء.

الفحوص التي تكتب سجلات جرت في قاعدة معزولة على الخادم المستقل، ومعاينتها على المنفذ8001؛ قاعدة المشروع ومعاينتها على8000 منفصلتان. لم تُحذف بيانات المستخدمين أو المعاينة السابقة. التقرير وخطوات المراجعة المفصلة في [SPRINT_3_REPORT.md](SPRINT_3_REPORT.md)، والتقدم في [SPRINT_3_PROGRESS.md](SPRINT_3_PROGRESS.md). لا حاجة لإعادة التوليد أو تكرار سيناريوهات الكتابة المنجزة عند الاستئناف.
