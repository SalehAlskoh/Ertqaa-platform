## الامتداد الإضافي الوحيد

فُحصت البنية الفعلية لـenrollments على MariaDB 11.4.13، ولم توجد أعمدة مكافئة. Migration جديدة تضيف:

| العمود | النوع | القاعدة |
|---|---|---|
| confirmed_by_user_id | BIGINT UNSIGNED NULL + FK users.id RESTRICT | هوية الحساب المصادق عليه الذي أكد العملية؛ لا تقبل من المتصفح |
| paid_amount | DECIMAL(10,2) NULL + CHECK >= 0 | مبلغ التحصيل الكامل؛ NULL محفوظ للتاريخ القديم فقط |
| paid_at | DATETIME NULL | ساعة الخادم UTC عند التحصيل المدفوع؛ NULL للتسجيل المجاني |

يستمر enrolled_at لتاريخ التأكيد. لا payments أو is_paid أو تاريخ تأكيد مكرر. تظل أعمدة الامتداد nullable لحماية التاريخ، وتفرض الخدمة قيمها في كل تأكيد جديد. لا تُعدّل Migrations المنفذة، ولا تُحذف سجلات أو يُعاد تهيئة جدول.

## الدورة وقواعد المال

pending → awaiting_confirmation (مراجعة Admin/Staff + reviewer/time + expires=now+48h) → completed مع Enrollment active داخل معاملة واحدة. pending → rejected بسبب إلزامي. pending/awaiting_confirmation → cancelled بواسطة صاحب الطلب. العرض المنتهي يعتبر expired فورًا، ويمكن لأمر مجدول تحديث الحالة وإشعاره مرة واحدة. completed لا يعاد فتحه؛ Enrollment active → withdrawn مع withdrawn_at وحفظ بيانات التحصيل.

- fee=NULL غير محدد: يُمنع التأكيد. fee=0 مجاني: paid_amount=0 وpaid_at=NULL. fee>0: العملة مطلوبة والمبلغ يطابق الرسوم كاملة، دون أقساط أو خصم.
- المقارنة المالية بسنتات صحيحة مشتقة من سلاسل عشرية، دون FLOAT/DOUBLE.
- confirmed_by_user_id من auth()->id()، وpaid_at/enrolled_at من ساعة الخادم. لا تقبل هوية الطالب أو حالة الطلب أو بيانات التأكيد المحمية من Form.
- بعد وجود تسجيل مؤكد بقيمة paid_amount موثقة (بما فيها صفر للمجاني) أو paid_at، تثبت رسوم المجموعة وعملتها حتى لو انسحب الطالب، كي لا يُعاد تفسير التاريخ المالي. لا استردادات أو بطاقات أو فواتير.

## السعة والتزامن

occupied = التسجيلات active عبر applications. reserved = awaiting_confirmation مع offer_expires_at > now واستبعاد وجود Enrollment نشط لنفس الطلب. available=max(0,capacity-occupied-reserved). pending لا يحجز. انتهاء الحجز لا يعتمد على Scheduler.

ترتيب مورد المقاعد ثابت: قفل المجموعة ثم الطلب ثم التسجيل. جميع التحولات والسعة تستخدم معاملة وقفل المجموعة، وإعادة القراءة داخلها؛ القيد UNIQUE(application_id) يظل قائمًا. الإشعارات تُحفظ في المعاملة نفسها بعد تحول فعلي، فلا تتكرر مع إعادة الطلب أو rollback/retry.

جدولة المحاضرات وتغيير المحاضر يقفلان صفوف المحاضرين تصاعديًا قبل المجموعة ثم المحاضرة، مع التحقق من عدم تغير الإسناد أثناء انتظار القفل. تُرفض التداخلات نصف المفتوحة starts < other.ends AND ends > other.starts بين المحاضرات scheduled. توليد الجدول لا يسمح بمجموعة لها أي محاضرات، ويخصص الترقيم خادميًا تحت قفل المجموعة. لا postponed أو تاريخ تغييرات أو جدول تكرار.

## حفظ البيانات

لا تُحذف الطلبات أو التسجيلات أو المحاضرات أو حسابات وبيانات المعاينة القائمة. الإلغاء والانسحاب حالات تحفظ التاريخ. تبقى FK/UNIQUE والأدوار الحالية. فحوص الكتابة والحالات الحدية ستنفذ في قاعدة معزولة، دون تعديل بيانات المشروع لمجرد التحقق.
