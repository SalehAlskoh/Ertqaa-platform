## ما كان موجودًا وما استُكمل عند الاستئناف

كانت الشاشتان المرجعيتان والدفعات A–C مكتملة ومفحوصة، وتغييرات D موجودة على القرص دون قبول نهائي. فُحص Git Status وGit Diff وBlade وCSS وJavaScript والمكونات والتوثيق، وأعيد استرجاع بيانات مشاريع Stitch والشاشتين دون توليد مكرر أو حذف العمل السابق.

استُكملت مراجعة D، وأُصلح Escape للقائمة العامة عندما يبقى التركيز على زر الفتح نفسه. شملت المراجعة صفحات المحاضر الثلاث والترقيم العربي وصفحات الأخطاء، والبناء وتجميع Blade وPHP lint والفحص الفعلي، وحفظ صور التسليم. أُنشئ [UI_REDESIGN_PROGRESS.md](UI_REDESIGN_PROGRESS.md) ليحفظ حالة الاستئناف وخطوتها التالية دون أسرار.

تفاصيل المقارنة، أنظمة التصميم، مصادر الخطوط والفروق عن المرجع في [STITCH_SOURCES.md](STITCH_SOURCES.md). لم تُعدّل مشاريع Stitch ولم تُولد شاشات إضافية.

## الحفاظ على الوظائف

حُفظت بصمات 68 ملفًا للخلفية والإعدادات وMigrations والعقد والاعتمادات وملفي البيئة، بالإضافة إلى تعريفات Routes قبل التعديل. الفحوص المتكررة حتى نهاية D أكدت مطابقتها كلها؛ لم يحتج التصميم لتعديل Controller أو Model أو Policy أو Route أو مخطط قاعدة البيانات. لم تتغير وثيقة TRAINING_CENTER_DATABASE_SCHEMA.md أو الاعتمادات أو إعدادات Vite، ولم يبدأ Sprint 3.

بيانات العرض المرئي موسومة بـ«معاينة» وأُنشئت في التنفيذ السابق لفحص القوائم والترقيم والحالات. بقيت أربع حسابات معاينة وثلاثة تصنيفات و17 كورسًا وثلاث مجموعات محفوظة، امتثالًا لطلب الاستئناف الأخير بعدم حذف أي بيانات. هذه ليست بيانات مركز حقيقية ولا ثوابت في HTML؛ الأرقام تأتي من سجلات قاعدة البيانات الحالية. لم تُنفذ خطة تنظيف السجلات بعد الاستئناف.

رُصد عند الاستئناف حساب طالب إضافي خارج قائمة المعاينة المحفوظة؛ لم يُفترض ثبات البيانات خلال التوقف، وحُفظ الحساب كما هو. تطابقت بصمات الجداول الـ15 بعد استبعاد سجلات المعاينة مع لقطة الاستئناف، وتطابقت أيضًا سجلات المستخدم الأصلي وملفه ودوره مع البصمات الأولى. لا يطبع الفحص أسماء أو بريدًا أو كلمات مرور أو بيانات سجلات خامًا.

أرقام سجل الكورسات مأخوذة من Paginator الحالي، مع التصريح بنطاق «في هذه الصفحة» لمجاميع الصفحة. فحص مرشح المسودات أعطى ثلاث نتائج وثلاث مسودات وصفر منشور، ومجموع الساعات 127.50 للنتائج الظاهرة؛ لم تُستحدث استعلامات تجميع داخل Blade أو Controllers.

## الفحوص المنفذة

- نجح `php artisan view:cache` وPHP lint لجميع ملفات Views المترجمة الـ113. نجح `npm run build` بعد الدفعة الأخيرة وإصلاح Escape، مع تضمين ملف Cairo في ناتج البناء. لا تعني نتيجة البناء وحدها قبول المظهر؛ فُحص المتصفح والصور فعليًا.
- الكورسات وتفاصيل المجموعة: عرض 1440 و768 و375، RTL فعلي، وعرض المستند يساوي عرض النافذة دون تجاوز خارجي.
- درج القائمة: حالة hidden/inert وaria-expanded صحيحة، التركيز يدخل الدرج، Escape يغلقه ويعيد التركيز إلى زر الفتح.
- مرشح النشر ونتائجه وأرقام البطاقات تعمل ببيانات حقيقية مؤقتة.
- الدفعة A: الحقول وأفعال النماذج وCSRF محفوظة، ونموذجا الملف الشخصي يحتفظان بـPATCH وPUT. تسجيل غير صحيح أظهر خطأ التأكيد واسمًا وبريدًا محفوظين كـOld Input، مع إفراغ حقول كلمة المرور وعدم وجود IDs مكررة.
- الدفعة B: فحصت القوائم والتفاصيل العامة على المقاسات الثلاثة، ونجحت تصفية التصنيف والكورس والبحث بلا نتائج. الكورس والمجموعة غير المنشورين يعيدان 404، ولا تظهر بيانات اتصال المحاضر الخاصة للعامة.
- الدفعة C، قبل طلب الاستئناف الأخير: اختُبر إنشاء تصنيف معاينة وتحديثه وحذفه عبر الواجهة؛ لم يُحذف إلا السجل الذي أنشأه الفحص. بدأ حوار التأكيد بالتركيز على الإلغاء، وأغلقه Escape مع إعادة التركيز وبقاء السجل، ثم نجح الحذف بعد التأكيد الصريح. خطأ الاسم المطلوب احتفظ بالرابط المختصر وأظهر aria-invalid ورسالة عربية. نجح تحديث كورس ومجموعة ومحاضر وموظف معاينة مع حفظ مواعيد طرابلس، وتبديل وضع إنشاء الحساب يعطّل حقول الجزء المخفي ويحفظ شرط تأكيد الحساب الموجود. لم تُكرر هذه الكتابات أو عمليات الحذف بعد الاستئناف.
- الدفعة D: واجهات المحاضر الثلاث على المقاسات الثلاثة دون تجاوز خارجي أو IDs مكررة، وبخط Cairo محمّل. فُحصت 403 و404 و419 بالعربية وبنفس HTTP Status، دون عرض تفاصيل الاستثناء أو إضافة Routes.
- الانتقال العام للصفحة الثانية احتفظ بقيمة البحث «معاينة» وأظهر «عرض 13 إلى 14 من أصل 14 نتيجة»؛ لا توجد عبارات Pagination إنجليزية. Escape أغلق القائمة العامة وأعاد التركيز، بما في ذلك عند بقاء التركيز على زر الفتح.
- تنقل الموظف يقتصر على إدارة الكورسات والتصنيفات والمجموعات، وتظل إدارة الحسابات محجوبة عنه بـ403. لا يرى المحاضر إلا مجموعاته وملفه، ولا يرى الطالب روابط الإدارة. لم تُغيّر Gates أو Policies لتحقيق ذلك.
- التقييم البصري المستقل النهائي PASS في الجولة الأولى: 11 صفحة على 1440 و768 و375px، بإجمالي 33 حالة، مع فحص الصور الفعلية. تقرير التقييم والصور التفصيلية محفوظان في مجلد الجلسة المؤقت خارج Git؛ صور التسليم المختارة مرفقة أدناه.
- مرجع الصور الأصلي يحتوي تحصيلًا وتسجيلًا ومحاضرات وقاعات ومؤقتات غير منفذة؛ لم تُنشأ أزرار أو حقول أو بيانات وهمية لها.
- لم تُنشأ اختبارات PHPUnit أو Feature Tests آلية، ولم يُنفّذ Commit أو Push.

## ملاحظات التنفيذ

- عُدلت البنية الإدارية إلى قائمة جانبية يمينية وشريط علوي، مع تنقل عام مستقل على المسارات العامة حتى للمستخدم الإداري.

- كشف العرض الفعلي ParseError في ثلاث قوائم إدارية رغم نجاح view:cache؛ سببه التصاق إغلاق Named Slot بتعليمة endif. فُصلت حدود Blade، ونجح PHP lint لجميع ملفات Views المترجمة الـ109 قبل إعادة فحص المتصفح.
- استدعاء مساعد `python` فعّل مشغّل Windows الذي حدّث نفسه وبدأ تنزيل مفسر؛ أُوقفت العملية فورًا، واستُخدم PHP الموجود للفحوص. لم يُضف اعتماد Python للمشروع.
- أداة الالتقاط الكامل عرضت إزاحة لبعض الصفحات القصيرة RTL رغم صحة أبعاد DOM. تأكد العرض بلقطة Viewport صحيحة، واستُخدمت هذه الطريقة للصفحات القصيرة في صور التسليم؛ لم تُغيّر CSS سليمة لمعالجة مشكلة التقاط.
