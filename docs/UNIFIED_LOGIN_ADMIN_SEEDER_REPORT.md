# تسجيل الدخول الموحد وAdminSeeder

اكتمل التنفيذ والتحقق بتاريخ 2026-11-16. قرار صاحب المشروع: الاحتفاظ بالمدير الحالي دون تغيير، واختبار إنشاء المدير والدخول به في قاعدة معزولة فقط.

**حالة قاعدة المشروع**

يوجد حساب مدير نشط واحد مربوط بدور `admin`. نُفذ `DatabaseSeeder` على قاعدة `ertqaa_platform`: نجح `RoleSeeder` ثم تخطى `AdminSeeder` إنشاء الحساب برسالة واضحة لغياب قيم `SEED_ADMIN_*`. بقيت أعداد الصفوف وبصماتها في جداول بيانات المشروع الخمسة عشر كما كانت، بما فيها المستخدمون وكلمات مرورهم المجزأة والأدوار وروابطها. لم يُنشأ مدير جديد في قاعدة المشروع، ولم تُستخدم كلمة مرور مفترضة أو تُطلب كلمة المرور في المحادثة.

لم يُختبر تسجيل الدخول بالمدير الحالي في قاعدة المشروع، وفق قرار صاحب المشروع. جرى **اختبار دخول فعلي ناجح** عبر `/login` بالمدير الذي أنشأه Seeder في القاعدة المعزولة: وصل إلى `/admin/dashboard` وظهرت قائمة المدير وروابط إدارة الحسابات، ولم يظهر رابط لوحة الطالب لحساب المدير ذي الدور الواحد.

**سلوك Seeder**

- `config/admin_seed.php` يقرأ `SEED_ADMIN_NAME` و`SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD`؛ لا `env()` داخل Seeder، ولا كلمة مرور ثابتة.
- التنفيذ المحلي فقط (`APP_ENV=local`). ينشئ `RoleSeeder` الأدوار عند الحاجة، ثم يُنشأ المستخدم ويربط بالدور داخل Transaction، بحساب نشط وكلمة مرور مجزأة بـ`Hash::make()` وآلية النموذج الحالية.
- كلمة المرور الجديدة لا تقل عن 12 حرفًا مع أحرف كبيرة وصغيرة وأرقام ورموز. بيانات ناقصة تعني تخطي الإنشاء، وبيانات غير صالحة تعني الرفض دون حساب جزئي.
- تكرار التنفيذ لا يغير اسم مدير موجود أو كلمة مروره أو نشاطه أو أدواره الأخرى. يُفحص الدور المسجل فعليًا حتى لو كان الحساب معطلًا؛ لا يُعاد تفعيله تلقائيًا.
- بريد مستخدم لحساب بلا دور `admin` يسبب تعارضًا واضحًا دون ترقية الحساب.
- `DatabaseSeeder` ينفذ `RoleSeeder` ثم `AdminSeeder` دون مستخدمين تجريبيين أو حذف بيانات.
- بقي أمر `ertqaa:create-admin` الموجود كما هو بوصفه وسيلة بديلة؛ لم يُعدّل ملفه.

**تسجيل الدخول والعودة**

كانت صفحة Login موحدة وأولوية الأدوار والتنقل موجودة بالفعل، فحُفظت. لم تُنشأ مسارات أو صفحات جديدة للمصادقة، ولم تتغير Sessions أو CSRF أو Throttling أو Policies أو التسجيل العام أو تصميم Stitch.

أصبح `IntendedRedirect` يتحقق قبل إعادة التوجيه من الوجهة المحلية، ومن كونها مسار GET موجودًا، ومن Gates الحالية للمسار وPolicies وملكية السجل عند الحاجة. يُرفض الرابط الخارجي و`//` والشرطة الخلفية ومحارف التحكم والوجهات المفقودة أو غير المصرح بها، ويُستخدم `/dashboard` بدلًا منها. بقيت الوجهات الداخلية المسموحة وQuery Parameters سليمة، بما فيها المسافات المشفرة.

هذه مراجعة لسلوك سابق: كان الرابط المحلي غير المصرح به يُستخدم ثم يُرفض الوصول إليه بـ403؛ الآن يُستبعد قبل التوجيه ويُختار Dashboard المسموح. الطلب المباشر إلى الوجهة غير المصرح بها يظل 403.

أولوية الحساب متعدد الأدوار: Admin ثم Staff ثم Instructor ثم Student. جميع أدواره وروابط لوحاته المملوكة تبقى متاحة. مسارات الموارد تحترم أيضًا قيود ملكية صفحات الطالب وقائمة طلاب المحاضر، حتى للحساب متعدد الأدوار الذي يحمل دور Admin.

**نتائج التحقق**

- 57 تحققًا تشغيليًا معزولًا ناجحًا: غياب البيانات ونقصها، تجهيز الأدوار، قوة كلمة المرور وتجزئتها، إنشاء حساب نشط واحد، إعادة التنفيذ دون تكرار أو تغيير، حفظ تعدد الأدوار، عدم تفعيل المدير المعطل، تعارض البريد، وحظر الإنشاء في Production؛ كذلك Gates وروابط العودة وملكية الطلب والتسجيل والمحاضرة والمجموعة.
- نجح فحص Config Cache في عمليات PHP منفصلة: قراءة بيانات Seeder من كاش خاص خارج المشروع وإنشاء المدير به؛ ثم إزالة بيانات الإنشاء والكاش وإعادة Seeder دون حذف الحساب أو تغيير كلمة مروره.
- 84 تحقق HTTP ناجحًا باستخدام جلسات وCSRF حقيقيين: الدخول لكل دور، أولويات تعدد الأدوار، Sidebar، الضيوف، الحساب المعطل وبلا دور، صلاحية رابط العودة، ثبات أدوار الحساب بعد Login، ورفض حقن الدور في التسجيل العام. جرى احترام مهلة Throttling الحالية عند بلوغها أثناء الفحص، دون تعديل إعداداتها.
- فحص متصفح مستقل للحساب الذي أنشأه Seeder: دخول فعلي، توجيه إلى لوحة المدير، وفتح Sidebar ورؤية روابط المدير.
- لم يمنح تمرير `role` أو `roles` إلى Login أي دور إضافي. رفض التسجيل العام تمرير الدور، وأنشأ التسجيل الصحيح طالبًا فقط مع ملفه.
- نجح PHP Syntax للملفات الخمسة وLaravel Pint وBlade Compilation وRoute List. بقي `/login` له GET وPOST الحاليان فقط، وعدد المسارات 83 دون أي تعديل في `routes/web.php`.

مضافة: `database/seeders/AdminSeeder.php`، `config/admin_seed.php`، `app/Support/IntendedRedirect.php`، وهذا التقرير.

معدلة: `database/seeders/DatabaseSeeder.php`، `app/Http/Controllers/AuthController.php`، `.env.example`، `docs/LOCAL_DEVELOPMENT.md`.

حُفظت تعديلات المراحل السابقة. لم تتغير Models أو Policies أو Routes أو صفحات Blade أو CSS أو سكربتات التشغيل أو Migrations أو المرجع `TRAINING_CENTER_DATABASE_SCHEMA.md`. لم يُنشأ أو يُشغّل PHPUnit أو Feature Tests، ولا Commit أو Push. قاعدة الفحص مستقلة، وملفات اعتمادها خارج Git.

**الاستخدام لاحقًا**

للاستمرار بالمدير الحالي، اترك متغيرات Seeder فارغة وسجل الدخول ببيانات حسابك الحالية عبر `/login`. لتجهيز مدير جديد محليًا، ضع القيم الخاصة بك في `.env` فقط، ثم نفذ:

```powershell
php artisan config:clear
php artisan db:seed
```

بعد النجاح أزل كلمة المرور المؤقتة من `.env` ونفذ `config:clear` أيضًا لإزالتها من الكاش، أو أعد بناء الكاش بعد إزالة القيمة إذا كنت تستخدمه. الحساب القائم يبقى محفوظًا. التفاصيل في [دليل التشغيل](LOCAL_DEVELOPMENT.md).

لا عائق تقني معروف متبقٍ. حدود التحقق واضحة: الدخول الفعلي جرى في القاعدة المعزولة، والمدير الحالي في قاعدة المشروع بقي دون تعديل ودون تجربة كلمة مروره.
