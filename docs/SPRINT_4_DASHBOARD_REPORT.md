# تقرير Sprint 4A — لوحات الأدوار

اكتملت لوحات Admin وStaff وInstructor وStudent في المشروع الحالي بتاريخ 2026-11-15، اعتمادًا على بيانات قاعدة المشروع. لم تُعَد كتابة وظائف Sprint 1–3، ولم تُضف جداول أو Migrations أو Packages أو بيانات Demo إلى قاعدة المشروع.

**المؤشرات ومصادرها**

| اللوحة | المؤشرات | المصدر والضبط |
|---|---|---|
| Admin | حسابات الطلاب النشطة، الكورسات المنشورة، المجموعات، المحاضرون النشطون، الطلبات قيد المراجعة، الحجوزات الصالحة، التسجيلات النشطة، محاضرات اليوم المجدولة | `users.is_active` مع `roles`، و`courses.is_published`، وتجميع `training_groups.status`، وحالات `enrollment_applications` و`enrollments` و`lectures`. الحسابات والطلبات والتسجيلات أرقام منفصلة. |
| Staff | الطلبات قيد المراجعة، الحجوزات الصالحة، المنتهية خلال 24 ساعة، التسجيلات المؤكدة اليوم، محاضرات اليوم المجدولة | نفس حالات التشغيل؛ `enrolled_at` ضمن اليوم المحلي للتأكيدات، بما فيها التسجيلات التي انسحبت لاحقًا. الحجز صالح فقط قبل انتهاء `offer_expires_at`. |
| Instructor | مجموعاته، طلابه النشطون دون تكرار، محاضراته القادمة، محاضرات اليوم المجدولة | قيد `instructor_user_id` على مجموعاته، وSQL `DISTINCT student_user_id` عبر التسجيل النشط، والمحاضرات المجدولة القادمة أو ضمن يوم طرابلس. |
| Student | طلباته قيد المراجعة، حجوزاته الصالحة، تسجيلاته النشطة، محاضراته القادمة | جميعها مقيدة بالمستخدم؛ المحاضرات القادمة من مجموعات تسجيله النشط فقط، دون مجموعات انسحب منها. |

المؤشرات تحسب في SQL، والقوائم الحديثة محدودة بستة سجلات والإشعارات بخمسة. العلاقات محملة مسبقًا. يظهر الطلب باستخدام `effective_status` الموجود، فتظهر نهاية المهلة فورًا دون انتظار جدولة مهمة. الإشغال يشارك منطق `TrainingGroupService`: تسجيل نشط أو حجز صالح لا يملك تسجيلًا نشطًا؛ مجموعات قرب الامتلاء منشورة/قيد التنفيذ وبنسبة 80% فأكثر.

اليوم من `Africa/Tripoli`، وتُحوّل بدايته وبداية اليوم التالي إلى UTC للاستعلام بمجال نصف مفتوح. جدول اليوم يعرض جميع الحالات الفعلية، والمؤشر يحسب `scheduled` فقط. القادم مجدول و`starts_at >= now()`.

سجل المدير يعرض أحدث ستة تسجيلات ذات `paid_amount` موثق، مرتبة بتاريخ التسجيل ومعرّفه، وبعملة المجموعة في كل صف. يحتفظ بالمنسحب ويبيّن التسجيل المجاني صفرًا دون تحصيل؛ لا جمع للعملات أو حساب أرباح أو افتراض استرداد. لا بيانات مالية للطلاب في لوحة المحاضر.

**الربط والحماية**

أُضيف `DashboardController` بأربعة إجراءات عرض و`DashboardDataService` كطبقة قراءة. أُضيفت أربع Gates مستقلة في `AppServiceProvider` لحماية كل لوحة على الخادم. الحساب متعدد الأدوار يحتفظ بجميع لوحاته؛ أولوية الدخول الافتراضية Admin ثم Staff ثم Instructor ثم Student عندما لا يوجد رابط عودة داخلي محفوظ وآمن. يبقى `/dashboard` موزعًا إلى الوجهة المناسبة. حافظ تعديل `AuthController` على تسجيل الدخول والجلسات والحدود الحالية، مع التحقق من رابط العودة؛ لم تتغير Policies.

| المستخدم صاحب دور واحد | Admin | Staff | Instructor | Student |
|---|---|---|---|---|
| Admin | 200 | 403 | 403 | 403 |
| Staff | 403 | 200 | 403 | 403 |
| Instructor | 403 | 403 | 200 | 403 |
| Student | 403 | 403 | 403 | 200 |

نجح أيضًا دخول الحسابات متعددة الأدوار إلى جميع اللوحات المسندة لها، وأولوية Admin ثم Staff ثم Instructor. الضيف يُحوّل إلى Login؛ الحساب بلا دور 403، والمعطل لا يدخل. الموظف ممنوع من قوائم إدارة الموظفين والمحاضرين، والمحاضر ممنوع من مجموعة محاضر آخر. العودة إلى صفحة لدور غير مملوك لا تتجاوز حماية 403.

فُضّلت بيانات النظام وهوية Cairo المحلية وRTL والألوان المعتمدة على الأرقام والحقول الوهمية التي اقترحها المصدر. لم تُنسخ القاعات أو الهوية الوطنية أو السندات أو POS أو الحضور أو الاعتمادات أو حالات غير مدعومة. لا رسوم بيانية أو نمو وهمي أو روابط غير تشغيلية أو اعتماد خارجي للخطوط.

أعيد استخدام `layout` و`stat-card` و`data-table` و`badge` و`application-badge` و`date` و`offer-deadline` و`capacity-summary` و`empty` و`page-heading` و`breadcrumbs` وSidebar وTopbar. أضيفت ستة مكونات مشتركة: `dashboard-panel` و`dashboard-quick-links` و`dashboard-applications` و`dashboard-lectures` و`dashboard-reservations` و`dashboard-notifications`. روابط الأدوار في Sidebar محمية ببواباتها، وأضيف رابط لوحة التحكم إلى التنقل العام. التنبيه المطلوب للطالب ظاهر مع عروضه الصالحة ومهلة كل عرض؛ لا تأكيد إلكتروني أو دفع.

**نتائج التحقق**

- 46 تحققًا تشغيليًا مستقلًا على قاعدة معزولة: مطابقة المؤشرات، الحجوزات المنتهية والدقيقة/الفارغة، استبعاد الانسحاب، سعة 80%، الطالب دون تكرار، خصوصية المجموعات والإشعارات، حالات المجموعات والمحاضرات، حدود اليوم والسنة في طرابلس، ونطاق القوائم.
- 174 تحقق HTTP ناجحًا، بما فيها مصفوفة الوصول وتعدد الأدوار والحساب المعطل، وروابط العودة الداخلية مع مسافات مشفرة، ورفض الوجهات الخارجية و`//` والشرطة الخلفية ومحارف التحكم.
- 119 رابط GET معروضًا فُتح بنجاح: Admin 39، Staff 30، Instructor 26، Student 24. تشمل الروابط Sidebar والعمليات والتفاصيل بحسب بيانات الفحص.
- تطابقت البطاقات المعروضة مع قيم طبقة القراءة لكل دور. نجحت الحالات الفارغة والأصفار للقوالب الأربعة. عدد الاستعلامات أثناء عرض Blade بعد تحميل البيانات: صفر.
- الاستعلامات لطبقة القراءة ببيانات الفحص: Admin 34، Staff 25، Instructor 13، Student 27؛ لا استعلامات إضافية عند قراءة علاقات الصفوف المعروضة. تختلف الأعداد في البيانات الفارغة، ولا تزيد لكل صف داخل القوائم.
- نجاح RTL وتحميل Cairo المحلي وعدم تجاوز عرض الوثيقة أو تكرار IDs في 12 معاينة: الأدوار الأربعة عند 1440 و768 و375. الجداول تمرر داخل حاوياتها. القائمة الجانبية تفتح من اليمين وتغلق بـEscape مع إعادة التركيز. اجتازت اللوحات الأربع تقييم تصميم مستقل بنتيجة `PASS` من الجولة الأولى. التقييم من نفس مزود النموذج لعدم توفر مزود آخر.
- نجاح `npm run build` و`php artisan view:cache`، وPHP Syntax للملفات الستة المعدلة/المضافة، وLaravel Pint و`git diff --check`.
- Route List يحتوي 83 مسارًا: احتُفظ بالـ79 السابقة وأضيفت اللوحات الأربع، دون تغيير أسمائها أو إجراءاتها السابقة.
- طابقت بصمات الصفوف وأعدادها في جداول بيانات المشروع الخمسة عشر حالة البداية. لم تتغير Models أو Policies أو Migrations أو المرجع أو Addendum أو ملفات الاعتمادات؛ 34 ملفًا محميًا مطابقًا للبداية. `.env` و`vendor/` و`node_modules/` غير متتبعة ومستثناة من Git.

لم يُنشأ أو يُشغّل PHPUnit أو Feature Tests. ملفات التحقق والاعتماد المؤقتة خارج المستودع؛ قاعدة الفحص مستقلة عن `ertqaa_platform`. لا Commit أو Push، ولا حذف سجلات أو حسابات.

**المشكلات والمعالجة**

كانت خدمة MariaDB المحلية الحالية على 3308 متوقفة؛ شُغلت بواسطة `scripts/start-local-db.ps1` دون تثبيت أو إعادة إنشاء بيانات. عولج رفض MariaDB استخدام aliases العدّ مع السعة داخل HAVING باستعلام فرعي ثم WHERE، مع بقاء منطق الإشغال كما هو ودون تغيير SQL Mode. انتهت جميع الفحوص المطلوبة بنجاح؛ لا عائق معروف متبقٍ ضمن Sprint 4A.

**المراجعة اليدوية**

الخادم المحلي للمشروع: `http://127.0.0.1:8000`. سجّل الدخول بالحساب الحالي ذي الدور المناسب، ثم افتح `/admin/dashboard` أو `/staff/dashboard` أو `/instructor/dashboard` أو `/student/dashboard`. يختار `/dashboard` الأولوية عند تعدد الأدوار، وتبقى روابط اللوحات المملوكة في Sidebar. استخدم حسابًا آخر للتحقق من 403. افتح قوائم التفاصيل والمحاضرات والطلبات من أزرار اللوحة، وجرّب القائمة الجانبية والجداول على الهاتف. بيانات المشروع الأصلية وحساباته لم تتغير.
