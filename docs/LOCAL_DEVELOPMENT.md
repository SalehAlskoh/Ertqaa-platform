# تشغيل ارتقاء محليًا

## قاعدة البيانات المستقلة

هذه البيئة تستخدم MariaDB **11.4.13** محمولة خارج XAMPP:

- المجلد: `C:\Users\hp\AppData\Local\Ertqaa-MariaDB-11.4.13`.
- العنوان: `127.0.0.1:3308`، قاعدة المشروع: `ertqaa_platform`.
- `DB_CONNECTION=mysql`، الترميز `utf8mb4`، Collation هو `utf8mb4_unicode_ci`.
- حساب التطبيق `ertqaa_app` محصور بهذه القاعدة، وكلمة مروره داخل `.env` المتجاهل في Git.
- بيانات الإدارة المولدة محفوظة في `.env` داخل مجلد التشغيل المستقل؛ لا تُنسخ إلى المستودع ولا تُعرض في السجلات.
- الخادم ليس خدمة Windows، لذلك يحتاج تشغيلًا بعد إعادة تشغيل الجهاز. لا يلزم تشغيل MySQL من XAMPP للمنصة.

من جذر المشروع في PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local-db.ps1
php artisan config:clear
php artisan migrate
php artisan db:seed --class=RoleSeeder
php artisan serve --host=127.0.0.1 --port=8000
```

افتح `http://127.0.0.1:8000`. الأصول مبنية بالفعل؛ بعد تعديل الواجهات شغّل `npm.cmd run build`، أو `npm.cmd run dev` في نافذة أخرى أثناء التطوير. لا تشغّل `composer setup` لإعداد مشروع قائم؛ فهو يولّد مفتاح تطبيق جديدًا.

إذا غاب مجلد التشغيل في جهاز آخر، جهّز نسخة MariaDB مستقلة مدعومة ببيانات جديدة وبيانات اتصال خاصة بذلك الجهاز؛ ملف `.env.example` قالب وليس بيانات دخول جاهزة. الحزمة المستخدمة هنا من [أرشيف MariaDB الرسمي](https://archive.mariadb.org/mariadb-11.4.13/winx64-packages/)، وقد طابقت بصمة SHA-256 المنشورة قبل فكها.

## أول حساب مدير

```powershell
php artisan ertqaa:create-admin --name="اسم المدير" --email="admin@example.com"
```

يطلب الأمر كلمة مرور مخفية وتأكيدها، بطول 12 حرفًا على الأقل. لا تمرر كلمة المرور كوسيطة أمر. عند وجود البريد مسبقًا يرفض الأمر إنشاء الحساب أو تغيير أدواره. للأتمتة المحلية الموثوقة، يدعم `--password-stdin --no-interaction` مع `--name` و`--email`: يُقرأ سطران من stdin (الكلمة ثم تأكيدها)، دون طباعتهما أو حفظهما في الكود. لا يوجد حساب مدير افتراضي أو كلمة مرور ثابتة.

التسجيل العام ينشئ طالبًا فقط. أنشئ الموظفين والمحاضرين من قوائم المدير. لإضافة دور إلى حساب موجود، ابحث ببريده الدقيق وراجع هويته ثم اختر نمط الحساب الموجود وأكد العملية؛ لا تتغير كلمة مروره أو أدواره السابقة.

## مراجعة يدوية

1. سجّل طالبًا، راجع ملفه، عدّل بياناته وكلمة مروره، ثم جرّب الدخول والخروج.
2. بحساب المدير أضف تصنيفًا وكورسًا، وانشره. جرّب البحث والتصفية والتعديل.
3. أضف محاضرًا جديدًا أو اربط حسابًا موجودًا بعد التأكيد. أنشئ موظفًا من قائمة الموظفين.
4. أنشئ مجموعة واختر كورسًا ومحاضرًا نشطًا. جرّب السعة صفرًا والتواريخ المعكوسة: يجب رفضهما.
5. جرّب نشر مجموعة لكورس غير منشور: يجب رفض العملية. إلغاء نشر الكورس يخفيه ومجموعاته عن العامة.
6. ادخل كمحاضر: تظهر مجموعاته فقط؛ تغيير رقم الرابط إلى مجموعة محاضر آخر يُرفض بـ403.
7. ادخل كموظف: إدارة التصنيفات والكورسات والمجموعات متاحة، وإدارة المحاضرين والموظفين ممنوعة.
8. عطّل حسابًا مؤقتًا: تُرفض محاولات دخوله، وتُبطل جلسته عند طلب صفحة محمية.
9. جرّب حذف تصنيف مرتبط بكورس، أو كورس مرتبط بمجموعة: تُرفض العملية. استخدم إلغاء النشر للحفاظ على التاريخ.
10. جرّب الواجهات على الهاتف. فترة التسجيل تُدخل وتُعرض بتوقيت `Africa/Tripoli` وتُخزن UTC.

العرض العام للمجموعات محصور حاليًا بالحالة `published` مع كورس منشور، حتى لو انتهت فترة التقديم. لا يوجد زر تقديم فعلي أو نظام دفع. بقية حالات المجموعة محفوظة كما في العقد، دون اختراع مصفوفة انتقال حالات جديدة. دورات التسجيل والمحاضرات والإشعارات التشغيلية مؤجلة.
